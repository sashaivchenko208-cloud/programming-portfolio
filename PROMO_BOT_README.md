# Бот розыгрышей и промоакций — прототип логики

Тестовое MAX. Python 3.10+, только стандартная библиотека. **Это проверенное ядро и вспомогательный API-клиент, не готовый к эксплуатации чат-бот.** Живого подключения к MAX нет; webhook, экранные кнопки и баннер не подключены. Работа подготовлена с помощью Codex.

## Запуск и тесты

```sh
python3 bot.py
python3 -m unittest -v
```

Демо запускается в памяти на явно фиктивном партнёре и коде DEMO-001, внешних запросов не отправляет. 10 тестов выполнены успешно.

## Реализовано

- SQLite, транзакции BEGIN IMMEDIATE, уникальные ограничения промокодов и пар пользователь/день.
- Один промокод пользователю за день; повтор возвращает тот же код. Исчерпание не блокирует регистрацию.
- Регистрация после положительного результата проверяющей функции; ошибки проверки не засчитываются как подписка.
- Один шанс за активный день независимо от числа действий; фиксированная десятидневная кампания и максимум 10 шансов. Дата — Москва.
- Раздел шансов: даты, партнёры, оставшиеся дни, описание главного приза.
- Ежедневный выбор без повторов; финальный взвешенный выбор 5 уникальных победителей по 2 билета и резервов. Вероятность очередного выбора пропорциональна числу активных дней; после выбора пользователь исключается из пула.
- Сохранение снимка участников и победителей; повторный вызов возвращает тот же розыгрыш. Выбор secrets.randbelow, не небезопасный псевдослучайный seed.
- Подтверждение администратором до формирования очереди уведомлений; повторное подтверждение не дублирует очередь.
- Имя/фамилия только с явным согласием; непобедитель не может подтвердить приз.
- Замена неответившего победителя резервом только после переданного срока; история замены сохраняется, подтвердившего приз заменить нельзя.
- CSV-выгрузка результатов и статистика запусков, запросов, выдач, остатков и участников.

## MAX API

`max_client.py`: проверка подписки и отправка сообщения, токен передаётся в Authorization, HTTP timeout 10 секунд. Живые запросы **не выполнялись**. Боту нужны права администратора канала. Токен следует читать из переменной окружения, не хранить в коде. TLS-проверка не отключается.

Сверенные официальные методы:
- https://dev.max.ru/docs-api/methods/GET/chats/-chatId-/members
- https://dev.max.ru/docs-api/methods/POST/messages

Адрес сервиса: https://platform-api2.max.ru. Для подписки используется фильтр user_ids и проверка members. Методы configure_day, draw, approve, promote_reserve и export_draw предназначены для доверенного администраторского процесса; они не должны открываться через публичный endpoint без авторизации.

## Что осталось до полного соответствия

1. Webhook-адаптер MAX с проверкой секрета, дедупликацией входящих событий и маршрутизацией всех кнопок. Приветственное меню сейчас возвращается как структура данных; баннер не предоставлен.
2. Настоящие партнёры, десять дат, каналы, коды, инструкции, правила акции и сроки получения приза. В демо всё явно синтетическое.
3. Проверка API в тестовом канале, авторизация административного интерфейса, планировщик розыгрышей и доставка очереди уведомлений с повторами, rate limits и защитой от двойной отправки.
4. Повторная проверка подписки перед выбором победителей: сейчас хранится факт проверки при регистрации. Если пользователь отписался позднее, живую проверку ещё нужно добавить.
5. Форма согласия с версией текста и получателем, правила хранения/удаления персональных данных; их защищённая передача партнёру. В CSV имена не экспортируются.
6. Нагрузочные/конкурентные тесты, миграции схемы, deployment и end-to-end тесты реального бота.

Прототип можно рассматривать как частичное решение для технического обсуждения. Полная готовность к эксплуатации и полное выполнение задания не заявляются.
